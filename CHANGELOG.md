# Changelog

## 2026-11-11
- **feat:** When Claude gives no genre and Last.fm and Deezer disagree, the genre question goes to whoever added the track with only the genres the two sources named, saying the sources disagree. They disagree only when each names a genre the other does not say, not even as a broader or more exact one under the hierarchy: Hip-Hop against Rock is a disagreement, while naming more («hip hop, electronic» against «electronic»), a more exact genre (Metal against Rock, DnB against Electronic) or both («electronic, hip hop» against «drum and bass», giving Hip-Hop and DnB) is agreement, and the sources decide. Until someone picks, the track keeps the first source's genre (if it could be saved), so nobody answering, «Не знаю», a track added by an unknown account, or a track not saved to the playlist leaves it with that genre; the question and the «Не знаю» answer name that genre. A pick now replaces a genre the bot found, but never a pick already made. With nothing found the question still offers all 11 genres. Backfill and import ask nobody, so for them the first source settles a disagreement.
- **feat:** Claude now decides the genre with what Last.fm and Deezer found, and Deezer is a new source (`app/services/deezer.py`):
  - Last.fm (tags of the track, else of its artists) and Deezer gather what they know; Claude picks one to three of the 11 genres with that as hints, each hint naming the playlist it leads to, so it can make a broad «Electro» exact.
  - Only the 11 genre names or their tags count in Claude's answer (split on commas, semicolons, slashes or new lines; list markers, quotes, a final dot and notes in brackets, even with commas inside, are ignored); anything else in it is dropped. An answer that says «unknown» or «не знаю» anywhere counts as not knowing.
  - Without Claude's answer (it does not know, has no credit or does not answer) the first source that knew decides: Last.fm track, Last.fm artists, Deezer (changed the same day: sources that agree decide, and in the duplicate watcher a disagreement goes to a person, see the first entry). A source not answering with nothing found asks nobody, as before.
  - Deezer gives the genre of the track's release, found by ISRC with no key. The label or music distributor sets it at upload, so even little-known tracks have one: of the 5 tracks no source knew on 2026-11-10, Deezer gives Metal, Rock and Electronic + Hip-Hop for 3.
  - Deezer genres map by their stable id, including ids missing from its genre menu (Country, Indie Rock, Techno/House, Reggaeton, Film Scores). «Alternative», «Musique russe» and genres with no TURDOM playlist (Reggae, Blues, regional ones) decide nothing. Indie Rock gets the tag Last.fm gives the same style, so both land in the same playlist.
  - The release must be the track artist's own and not a compilation: Deezer can give a soundtrack or another artist's release for an ISRC (seen for «Sweet Disposition», given as the (500) Days of Summer soundtrack).
  - Deezer has no DnB, Phonk or Lo-fi genre (Chill only through Jazz); that is what Claude's word is for. Fewer genre questions go to people.
  - `/backfill_genres reset` now asks Claude about every track: hours and a couple of dollars for the whole base.
- **test:** Tests never reach Deezer either.
- **feat:** When nobody knows a new track's genre, the bot asks whoever added it. Once the duplicate watcher saves the track and finds no genre, that registered person gets a private message with the track, the 11 genre playlists as buttons with ticks (several allowed), «Сохранить» and «Не знаю» (`app/bot/genre_question.py`). «Сохранить» saves the ticked genres as tags the distribution understands, unless the track got a genre meanwhile (changed the same day: a pick replaces a genre the bot found, see the first entry), and marks them as a person's pick (`tracks.genre_approved`). The answer says where the track goes: the genre hierarchy applies to picks too, so Metal and Rock ticked together give «Жанр: Metal (Rock не добавлен: с Metal трек в Rock не идёт)». «Не знаю», or a track added by a Spotify account the bot does not know, asks nobody else: the track stays without a genre and is listed in `/playlist status`. An answer that comes after the session reaches the genre playlists with a repeated `/distribute N`. A tap on a question Telegram no longer shows the bot is answered «Вопрос устарел» and logged.
- **feat:** Last.fm gives tags of the track, else of its artists (the first of up to three with genre tags); weak tags (count below 20) are ignored. When a source does not answer (network, overload, rate limit) and nothing was found, nobody is asked. A source that cannot be used at all (no key, a key the service refuses, a retired Claude model, an empty Anthropic credit balance or a spending limit reached) counts as absent, so people are still asked. A Claude call gives up after 30 seconds, so a hang cannot stall the watcher.
- **change:** The bot no longer uses OpenAI: GPT-4o-mini gave genres, now Claude does. The `openai` package and `OPENAI_API_KEY` setting are gone; a key left in `.env` is ignored. Claude's answer is read through the same tags a person's pick uses, so Hip-Hop and DnB come through (GPT's never did).
- **feat:** A track that already has a genre, found earlier or picked by a person, keeps it and is not looked up again when it is added to another playlist. `/backfill_genres reset` keeps the genres people picked, and a backfill never overwrites a genre saved while it runs; it pauses after a failed track too.
- **fix:** A track listed twice in a playlist is handled once per watcher pass. It used to get the dropped-before warning twice, and the second copy of a suspected duplicate was saved as if it were clean.
- **fix:** The Last.fm API key no longer reaches the log: httpx's line for every request (its URL holds the key) is off, and a Last.fm HTTP error logs only its status. «No such track or artist» is logged at debug level.
- **test:** The test suite no longer calls Last.fm or Anthropic with the keys of a local `.env`.
- **ops:** `constraints.txt` pins every package to the versions the running image has (aiogram 3.31.0, anthropic 2.7.0, …), and the Docker build installs with it. Without it, dropping `openai` from `pyproject.toml` would make the rebuild fetch the newest version of everything.
- **docs:** The docs describe how the genre is really found (Last.fm, Deezer, Claude, the person who added the track), not Spotify artist genres.

## 2026-11-10
- **feat:** Pressing «Оставить» on a suspected duplicate or a previously dropped track is now remembered for that one playlist while it is open (nothing is stored for a closed or unknown playlist, which is never checked). The duplicate watcher skips the track there the way it skips a thematic playlist; `/scan` skips it too and reports how many it skipped. The same track added to another playlist is still checked: while its playlist is open, the kept copy no longer stops the ISRC and fuzzy steps from finding an older lookalike. The kept track is saved like any other track of the playlist, so it gets a genre and facts and goes through distribution. Kept and thematic tracks now get an ISRC lookup before saving when Spotify left it out (other tracks already had one in the duplicate check). Pressing «Удалить», or the track leaving an open playlist, forgets the decision.
- **fix:** Editing a message after «Оставить», «Удалить», approve, deny or a join request keeps its bold text and links, escapes user text (`message.html_text`) and shows no link preview. The join request from `/join` and from the old join button escapes the user's name. «Оставить» and «Удалить» take the buttons away while working; they come back only if saving fails or the track could not be removed from Spotify. Auto-removal notices label each match by its kind instead of calling every non-exact match ISRC.

- **fix:** ISRC was never read: tekore returns `external_ids` as a dict, while the code used `getattr(external_ids, "isrc", None)`, so every track was stored without it and the ISRC duplicate step never fired. Added `extract_isrc`, used in all 4 places.
- **data:** Filled `tracks.isrc` for 2962 of 2964 tracks from Spotify (one-off script, no duplicates removed). Same-recording pairs across history: 6, latest in TURDOM#93.
- **feat:** New playlist no longer notifies anyone automatically. The admin gets a private picker with a tick per registered user and a Send button (`app/bot/playlist_notify.py`).
- **fix:** ISRC match ignores modified versions (remix, sped up), which stay sibling warnings. Watcher upsert now fills a missing ISRC on known tracks. Playlist names are escaped in "created" messages.
- **db:** Migration 69: index on `tracks.isrc`.
- **ops:** Spotify refresh tokens now expire after 6 months: re-run `/auth` by about 2027-05-08.
